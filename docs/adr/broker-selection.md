# 対象証券会社選定および連携方式検討

## 対象証券会社選定方針

国内証券会社の利用状況調査によると、楽天証券およびSBI証券が利用率・口座数ともに国内トップクラスである。

- 利用率
  - 楽天証券: 62.7%
  - SBI証券: 42.7%

- 口座数
  - SBI証券: 約1,300万口座以上
  - 楽天証券: 約1,300万口座以上

出典:

- https://tag-studio.co.jp/news/sec-user-survey-2025/
- https://zuu.co.jp/media/stock/ranking-criteria

以上より、本システムは日本国内の個人投資家の大部分をカバーすることを目的として、SBI証券および楽天証券を優先対応対象として検討する。

## 証券口座ごとのデータ連携方法整理

| 項目 | 楽天証券 | SBI証券 |
| :--- | :--- | :--- |
| 連携方法 | 楽天RSS | Hyper SBI 2 画面操作※1 |
| 提供元 | 楽天証券 | SBI証券 |
| 対応市場 | 国内株 | 国内株 |
| リアルタイム株価取得 | ○ | ○ |
| 自動発注 | ○ | △※2 |
| 必要アプリ | マーケットスピードII | Hyper SBI 2 |
| 裏アプリ常駐 | 必須 | 必須 |
| 対応OS | Windows | Windows※3 |
| Pythonからの利用 | ○ | △※4 |
| API利用料 | 無料 | - |
| 保守性 | ○ | ×※5 |

> ※1 補足
> SBI証券の個人開発者向け公式株式売買APIは確認できなかったため、Hyper SBI 2 のGUI操作による実装を想定している。
> インターネット上で紹介されているAPIの `localhost:18080` を利用した実装例は、三菱UFJ eスマート証券（旧auカブコム証券）のkabuステーションAPIに関する情報が含まれており、SBI証券口座のみで利用できることを確認できなかった。

> ※2 補足
> GUI操作によって自動発注を実現できる可能性はあるが、公式なプログラム連携手段ではないため安定性に課題がある。

> ※3 補足
> Hyper SBI 2 はmacOS版も提供されているが、自動売買実装ではWindows向けGUI自動操作ライブラリの利用を前提とするため、サポート対象はWindowsとする。

> ※4 補足
> Pythonから直接利用できる公式APIは確認できていない。PythonによるGUI操作であれば実装可能と考えられる。

> ※5 補足
> GUI操作は画面レイアウト変更やアプリケーションアップデートの影響を受けやすく、保守コストが高い。また動作の安定性にも課題がある。

## 結論

本システムでは、日本国内の個人投資家の大部分をカバーすることを目的として、SBI証券および楽天証券を優先対応対象として検討した。

調査の結果、楽天証券は楽天RSSによる安定したプログラム連携手段が提供されており、Pythonを用いた自動売買システムの実装が可能であることを確認した。

一方で、SBI証券については個人開発者向けの公式株式売買APIを確認できず、自動売買を実現する場合はHyper SBI 2のGUI操作に依存する可能性が高い。

GUI操作による実装は以下の点より、安定したサービス提供が困難である。

- 画面レイアウト変更の影響を受ける
- アプリケーションアップデートで動作しなくなる可能性がある

以上より、本システムの初期実装では楽天証券のみを対応対象とし、楽天RSSを利用した自動売買機能を実装する。

なお、SBI証券については将来的に安定した公式連携手段が提供された場合に対応を検討する。
